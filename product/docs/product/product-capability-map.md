# GridPulse product capability map

## Global destinations

| Destination         |                                            Finder |           Connect |      Full | Empty-state behavior                             |
| ------------------- | ------------------------------------------------: | ----------------: | --------: | ------------------------------------------------ |
| Sites               |                                         Available |         Available | Available | Explain how to create the first site.            |
| Power Finder        |                                         Available |         Available | Available | Allow a new site screening.                      |
| Constraint Explorer | Public illustrative and available project results |         Available | Available | Explain required assessment inputs and evidence. |
| Planner             |                                         Available |         Available | Available | Explain required site and load assumptions.      |
| Activation          |                                 Prerequisite page |         Available | Available | Never silently redirect.                         |
| Operations          |                                 Prerequisite page | Prerequisite page | Available | Never imply live control.                        |
| Evidence & sources  |       Public catalog; private ledger when enabled |         Available | Available | Show methodology without authentication.         |
| Reports             |                         Preview and prerequisites |         Available | Available | Show required canonical artifacts.               |

## Workflow

`Screen → Compare → Plan → Enquire → Verify → Decision package`

Evidence is cross-cutting and is not a numbered terminal step. Capability availability and workflow prerequisites are related but distinct: product mode controls whether a service exists; project state controls whether the user can use it for a particular site.
