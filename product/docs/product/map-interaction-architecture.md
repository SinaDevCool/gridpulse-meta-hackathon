# Production map interaction ownership

This document defines the single production owner for each map concern. The backtesting repository
is not a runtime dependency and must not be imported into the product application.

| Concern                                           | Canonical owner                                    |
| ------------------------------------------------- | -------------------------------------------------- |
| MapLibre lifecycle, sources and rendered layers   | `src/components/product/PowerFinderMap.tsx`        |
| Reusable legend interaction and accessibility     | `src/components/product/InteractiveMapLegend.tsx`  |
| Layer availability, evidence and page support     | `src/features/map/map-layer-registry.ts`           |
| Presets, capacity ranges and temporary isolation  | `src/features/map/map-filter-state.ts`             |
| Shareable isolation query state                   | `src/features/map/map-url-state.ts`                |
| German voltage classification and expressions     | `src/features/power-finder/voltage-style.ts`       |
| Generation, storage and evidence visual classes   | `src/features/map/map-visual-registry.ts`          |
| Runtime source health and coverage reconciliation | `src/features/map/map-source-registry.ts`          |
| Public viewport and tile transport                | existing Power Finder API and tile endpoints       |
| Power Finder workflow composition                 | `src/routes/power-finder.tsx`                      |
| Constraint-only controls and findings             | `src/routes/constraint-explorer.tsx`               |
| Theme selection and persistence                   | existing theme provider and semantic CSS variables |

## Boundaries

- Power Finder and Constraint Explorer reuse the same map and infrastructure styles.
- A layer toggle controls participation; `Only` temporarily isolates one legend dimension.
- Changing a preset never creates a second map instance or copies feature data.
- Registered generation and storage are nearby asset context, never available connection capacity.
- Unknown voltage and unavailable registry releases remain explicit states rather than false zeroes.
- Operator-confirmed evidence cannot be inferred from public, modelled or synthetic sources.
- Production fallback artifacts must be generated by the existing governed publishing path; map
  records must not be manually embedded in route components.
- Viewport GeoJSON and national vector tiles are independent transports. A viewport fallback must
  not hide a healthy national registry source, and a tile failure remains explicit source status.
- Germany-wide low-zoom generation and storage use deterministic aggregates owned by
  `power_finder_public_registry_tile`; exact published locations appear at investigable zooms.
- The runtime aggregate is read from `power_finder_registry_overview`; the governed data-release
  process refreshes that materialized projection after activating a new canonical MaStR release.
